## The OCR guarantee, and how to use it today

Operator requirement: a page may be read by the provider pipeline, by an AI run in the operator's own
terminal, or by the operator — and all three must give the same record with nobody skipping anything.

```
npm run rebuild:cli ocr forms                    # which forms, how many fields, how many mandatory
npm run rebuild:cli ocr instruction oath         # the exact brief EVERY route receives
npm run rebuild:cli ocr admit page1.json         # the gate; exits 1 on refusal
```

Adding a form or a field is a data edit in `src/domain/ocr/form-registry.ts`; the brief and the gate
both derive from it, so every route picks it up on the next run. Doc 06 §4.3 is the normative text.

## Open items this session recorded rather than hid

- **`read-excel-file` prioritizes usability over throughput** (~3 s for 2000 rows × 20 columns; very
  large files can overflow the stack). Operator HR exports are dozens to low hundreds of rows, so
  this is fine today. Revisit if a roster ever gets big.
- **The `.xlsx` fixture is produced by `write-excel-file`**, so it proves a real OOXML round-trip but
  NOT agreement with Excel's own output. That needs one live check against a real operator export —
  the `Xerox`/roster files the operator already has would do.
- **`@office-kit/xlsx` is worth revisiting at 1.0** — TypeScript-first, three modern dependencies,
  consumes openpyxl's fixture corpus. Refused now only because its API is declared unstable.
- **Fielded-PDF extraction still needs a library decision** before `extraction/extract-pdf-fields`
  can exist.
- **`npm audit` reports one high-severity advisory in `vite` 8.0.x** (Windows-only paths). It is
  pre-existing, dev/build-only, and unrelated to the new parsers; the fix is outside the stated
  dependency range.

## What to know before touching this code

- **Another session commits to this repo's `master` too.** That is normal, not corruption — commit
  your own category and let git interleave. Do not revert their work.
- **`npm run build:manifest` after ANY `src/domain/**` edit.** Those files are inside every
  descriptor's import closure. It also moves the dashboard's `wf <hash>` stamp, so the parity lane
  will go red until you refresh it with `npm run test:parity:update` — that is D145 working.
- **`src/domain/intake/**` must stay free of Node built-ins.** The mapping grid is a browser surface
  and `intake-mapping-boundary` enforces it.
- **`strict-boundary-schemas` scans `src/domain`.** A new exported interface needs a schema or an
  allowlist entry WITH a reason; `as` casts are refused outright (use a type predicate, or parse).
- **`fail-loud-catch-default` has no waiver.** A `catch` that assigns `true`/`null`/`{}` fails, even
  when it re-throws first. Return a discriminated value from the catch instead — see
  `attemptCoercion` in `src/domain/intake/validate.ts`.
- **A new guard file and its `guard-inventory.json` entry land in the SAME commit**, and append to
  the array rather than re-sorting it (the file is not sorted, and `json.dumps` with
  `ensure_ascii=False` will rewrite every `§` escape).
