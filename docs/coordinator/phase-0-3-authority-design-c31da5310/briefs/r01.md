## Goal

Land the normative design for **one SQLite-backed run-record lifecycle service** — the sole
existence and lifecycle authority for queued, current, terminal, archived, and tombstoned runs — as
required by D327, so that Phase 1.6 can implement it without redesign. Design only: **no file under
`src/`, `tests/`, `scripts/`, or `config/` changes** (D326). Fixture roadmaps under
`tests/unit/architecture/fixtures/` are guard fixtures and are also out of scope.

## The four leaves you must close (roadmap node `phase0-run-authority-design`, `builds:`)

1. One SQLite-backed run-record service is the existence and lifecycle authority for queue, current,
   terminal, archive, and tombstone states.
2. Typed create/read/update/delete and compare-and-swap transitions; tables stay private to adapters.
3. Spans, logs, receipts, captures, and artifacts remain append-only evidence linked to the run by
   stable run/session identity, never competing lifecycle authorities (D301: span files are never
   rewritten).
4. Queue ordering, first-eligible claim, retry/relaunch, archive, purge, and D308's terminal-only
   physical deletion behind an insert-only tombstone.

Doc `00` §0.3 Task 1 restates these as three checkboxes (identity + typed transitions; evidence
linkage; D308 + ordering/claim/retention/adapter boundaries). Both must be ticked with evidence.
