## Design decisions made in this run (all applications of D327/D330/D331)

1. **The upgrade is one stopped-system command**, `cli storage upgrade [--plan] [--json]`, under D181's
   admission plus the meta row's migration lease; **boot never crosses the floor** — a pre-floor
   authority is `upgrade-required` on every door, and 1.6 gates `#runMigrations` at the floor with a
   named read-only no-migrate open for `storage backup|doctor` and the upgrade's own preflight.
2. **Preflight is total and ordered (15 steps)**; steps 1–3 and 10 re-run after admission, and the live
   generation is re-read inside the exclusive transaction; the backup prerequisite binds the newest
   verified manifest to the live `authority_generation` (the command writes no backup, D322).
3. **One exclusive SQLite transaction** carries the ordinary chain, the D332 schema steps, the D290
   `integratedByVersion` freeze for 27/28/29, the completed D308 cascade for orphaned gate records, the
   tombstone ordinal backfill (the one admitted tombstone UPDATE, trigger dropped and re-created with the
   new columns in its equality set), the journaled `apply-settings` rewrite under the new
   `SETTINGS_SCHEMA_HASH`, the marked protected import, and the `committed` journal row.
4. **One journal, inside the database** (`authority_upgrades`, phases `baseline`/`planned`/`committed`/
   `settled`); it decides no existence, leaf or revision; a D321-regenerated root writes a `baseline`
   row so the boot matrix reads rather than infers. Analyst Q2 verdict adopted.
5. **Prepare/rollback files** under `<stateRoot>/upgrades/` (prepare is protected-class and transient;
   rollback retains prior bytes and is never backed up); `.env` is never written.
6. **Rollback** = the pre-upgrade backup (database) + the rollback file (files), through the 1.6
   restore command; the backup READ path admits `floor−1 ≤ schemaVersion ≤ CURRENT` against frozen
   per-version table sets while WRITE keeps the literal (blocker B1).
7. **Closed mixed-generation matrix** over (database, layout, journal); downgrade refused at the open
   ("newer than supported", as built) before any settings byte or migrated env value reaches `Config`.
8. **Preservation:** no lifecycle/evidence row rewritten; ordinals recovered from `run.queued` roots
   (D301-reconstructed roots admitted) with `ordinal_source` provenance, `unknown` + doctor finding when
   no root (argued safe; the third-watermark alternative rejected); tallies versioned, never re-settled;
   `config_snapshots` untouched with a closed-list RETIREMENT arm in `snapshot-generations`; historical
   exposure recorded, never claimed erased.
9. **`authority-unknown` is never re-admitted**; §2.5 item 6's "parked" is read as no row/no park; the
   finding carries `possibleExternalWrite`; protection is probe-then-park on the next attempt, subject
   to the node's `probePolicy`.
10. **Adapter expiry policy** (five rules) and roster: A0/A1 2.6, A2 2.6, A3 not an adapter (dead table,
    zero readers), A4/A5 1.6, A6/A7 permanent read-forward, A8 3.1; deletion tests in §5.2.
11. **Settings half:** 45 imported + 5 never-imported names; `settings.json` carried leaf-for-leaf under
    A0's frozen pre-floor schemas; seven tie-breaks by schema-parsed comparison (no normalization);
    canary references by per-kind schema (whitespace-only = absent); `migrated-refused` first boot by
    design with the plan's remove-list; provider keys classified by name, never read.
